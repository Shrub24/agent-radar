## 1. One execution constructor

- [x] 1.1 One creator with optional placement and launch intent, with identification as its own step. `ExecutionDraft::record` builds the record once; `create_execution` records it from its registration; `identify_execution` records the verified process and stores the supervisor's key before the transition that depends on it. ## 6. Rework: execution and attachment ownership

- [x] 6.1 One attachment record, no execution copy. Claim streams record attachment facts only (registration, subject, metadata, session, standing, grant time); identity, birth, binding, observation, placement, signal, exit, completion and pane cleanup are recorded on the execution stream and read from there. The combined fact type is gone (`Recorded::Attachment`/`Execution`), `reduce` is split by stream, `read_claim` composes the execution, `sync_claim` and its call sites are deleted, and `write_attempt` records execution changes on the execution stream instead of projecting a copy. A claim transition validates against the execution record, so the guards that refused an ended process survive without a copy. Verified: library 577 (including `a_claim_reads_its_execution_instead_of_carrying_a_copy`), control-plane 178 (1 ignored), every other target green; fmt, strict Clippy (large variants boxed) and OpenSpec clean. The absence of the copy is enforced by construction — the field and its synchroniser no longer exist — rather than by a test that could pass on a re-synchronised copy. `context/lifecycle.md` records the decision. The record shape changed, so earlier alpha state is refused and cleared with `radar reset --hard`.
- [x] 6.2 Accepted launch metadata is applied at grant with named intent taking precedence. The precedence itself landed in S1 (the execution's recorded intent wins when it is not the default); this pass supplied the evidence and corrected nothing: `a_launch_that_names_no_intent_continues_the_session_s_metadata` launches description-only, no-intent and restated-intent executions through `create_with_intent` and enrols each with the same session, so it proves a session's metadata outlives the process that named it, that absent intent retains it, and that restated intent replaces it. Verified by mutation: with the continued-metadata fallback replaced by a default, the test fails reading empty metadata where the session's owner, run and label should be.
- [x] 6.3 The hook promise chain is preserved and `session_start` awaits its initial response attempt (section 10, kept by maintainer decision; it holds up Pi startup while the daemon does not answer). Shutdown releases the exact claim; start sends registration/session and persists Radar's returned ID; heartbeats and release name it. Reserved IDs are resolved, and a new session on the registration releases the previous one in the daemon (10.9), which also covers a lost first response across shutdown/start. Deferred: carrying the start reason as context; no consumer needs it yet.

## 7. Rework: independent reservation and grant

- [x] 7.1 Maintained authority indexes over the claim log, shared write/replay invariants with incompatible authority refused as unreadable state, and most-recently-granted history (10.8, 10.15). Covered by the authority, replay and history tests in `events/tests.rs`.
- [x] 7.2 Restart failure paths (stop failure and successor failure after verified predecessor exit are now both covered at the domain level: `a_successor_that_fails_after_the_predecessor_exited_leaves_the_subject_detached` asserts no grant is restored, no reservation remains and the last grant is history; an exact-path control-plane test of stop failure remains optional). Covered: `restart_stops_the_verified_lead_then_launches_one_resumed_successor` (the happy path through the real control plane) and `restart_refuses_before_any_signal_when_the_session_context_changes` (refusal before any signal). Added this pass: `an_undispatched_restart_reservation_restores_its_incumbent` now starts from a *granted* incumbent and asserts the grant survives the reservation's withdrawal — with `cancel_reservation` also releasing the predecessor the assertion reads `None` and fails. Still to verify explicitly: a stop that fails cancels only the reservation while the incumbent keeps running, and a successor that fails after the predecessor exited leaves the subject detached rather than restoring the exited grant.
- [x] 7.3 Shared claim release and registration finalisation. Session shutdown normally releases the exact claim; `record_completion` now records the authenticated supervisor's completion *and* establishes the execution end and settles its outstanding claims through `record_exit_locked`, so a completed execution holds nothing without waiting for a pane notification or a sweep. `record_exit` (the unlocked recorder) delegates to the same locked settlement instead of keeping a second copy, and verified fallback observations and failed-launch withdrawal still enter it. Completion keeps spontaneous-exit pane retention separate from explicit close. Verified: `supervisor_completion_ends_the_execution_and_releases_its_claim` (the claim reads `Reserved` without the settlement and `Released` with it; the established end and the first report's status survive a replay) and `a_completion_after_a_verified_exit_records_the_status_it_carries` (a late report adds the status without moving the established end or resurrecting the released claim). Full Rust gate green: 577 library, 178 control-plane (1 ignored), every other target passing; fmt and strict Clippy clean.
- [x] 7.4 Reservation mismatch is settled at the shared attachment operation: a registration presenting another session than its own reservation intended records a typed failure, attaches under the ordinary rules, and publishes the failure on its execution, shown on the execution or agent row and in details (10.9, 10.13, 10.14). Another registration's reservation is never cleared. No automatic retry.
## 8. Rework: observation and joined rows

- [x] 8.0 Publication measured before optimising. `publication_cost_is_measured_before_any_of_it_is_optimised` builds a registry and times `registry_read::read` at 1, 25 and 100 subjects: 0.44 ms, 3.4 ms and 10.1 ms per publication, roughly linear at ~100 µs per published entry, with a generous 500 ms ceiling asserted. No optimisation was adopted: at these sizes the cost is dominated by per-subject reads that a 100-agent fleet still completes in a tenth of the TUI's refresh budget.

Read from the execution records themselves, so a launch in flight and a recipe launch with no spawn edge are published before anything presents; the attachment references are resolved from the claim standings, not from a copy. Wire moved to 20 (a published document changed), schemas regenerated, pi-radar contracts regenerated and its 134 tests updated for the new revision.

- [x] 10.3 Publish each execution's own current claim through the existing registration resolver, rather than joining another execution's grant/reservation by subject. Covered before and after successor grant.

- [x] 10.5 An already-recorded exit resumes shared claim finalisation on fallback observation. Interrupted-release coverage also retains the later supervisor completion status.
- [x] 10.6 Pane cleanup consumes the execution directly; no random subject/claim wrapper.
- [x] 10.8 Claim authority is a maintained cache over the claim log: subject grant, exclusive reservation, most recently granted claim and registration attachment. Writes and replay share the invariants (one grant, one reservation, one live attachment per registration); incompatible recorded authority is refused at replay; cancelling a reservation does not alter granted history.
- [x] 10.9 Claimless presence resolves the registration's reservation, else its applicable claim for that session, else releases the previous session's attachment and creates a new one. A named, released claim is never reopened. A registration presenting another session than its own reservation intended settles that reservation as released, retaining the intended session as evidence, and evaluates ordinary attachment. Remaining under 7.4: publishing that failed intent to the TUI.
- [x] 10.10 Row projection: a registration an agent row already shows is not shown again as an execution row; an ended execution no longer replaces its surviving pane (the pane is ordinary again); a live execution nests with its window as plain panes do. - [x] 10.12 The pane owns the reference to its occupant: `Pane.registration_id`, resolved in the collector and read by the tree (the tree's own placement join is deleted).
