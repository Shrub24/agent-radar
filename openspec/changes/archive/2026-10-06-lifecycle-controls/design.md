## Goals / Non-Goals

**Goals:** close a positively unmanaged pane/tab or ask the exact owner to close/restart a managed worker, with confirmation and honest outcomes.

**Non-Goals:** lead/standalone restart, fleet or restart-stale batches, workspace close, new tabs, steer/interrupt/extend, background-task controls, process kills, automatic retry, owner model prompts or a generic RPC framework.

## Decisions

1. **Two executors behind one operator flow.** Add normalized pane/tab close targets to the runtime seam with an explicit unsupported outcome for adapters that cannot close. Herdr retains its CLI grammar and bounded runner. A separate owner-control client handles managed requests. Rejected: a mux restart method or lifecycle over the metadata bus, neither of which can preserve owner accounting.
2. **Classify containment from current evidence.** Any Pi Herdsman metadata makes a Pi pane managed; local retained managed associations still prevent direct mux close. A Pi pane without managed metadata is uncertain, not unmanaged. No live agent and no retained/uncertain association, or a non-Pi agent kind Herdsman never manages, is positive unmanaged evidence. Normalize this classification at the adapter boundary if existing fields discard it; never import token names into UI policy. A tab with any managed or uncertain member is refused whole, without issuing per-member actions automatically.
3. **Freeze identity, not the cursor.** Confirmation stores operation, row identity, pane/tab and managed label/run/owner UUID plus available session cross-checks. Revalidate against the latest current observation on Confirm; identity or containment drift cancels with a reason. Direct mux close obtains another inventory immediately before acting and refuses changed containment. This reduces but cannot atomically eliminate races in a mux without conditional-close support; do not promise a transaction across Herdr inventory and close.
4. **A separate safe confirmation.** Keys are x (pane/agent close), X (selected row's tab close), r (managed restart). Unsupported task/workspace targets get a reason, not an implicit parent action. Filter-entry keys remain text. A modal names losses, with Cancel selected initially; Tab/arrow selects Confirm and Enter activates it, Escape cancels. Mouse activates only drawn buttons; a second click on a tree row still focuses, never confirms. No typing y to bypass target review.
5. **Owner identity is exact.** Owner directory is selected by parent session UUID; target requires the published label and run UUID. Include pane/session/path cross-checks when observed and echo operation/label/run in confirmation. Missing identity or owner is a refusal. Restart is only for an owner-advertised idle retained managed worker, not Radar's continuity-retained historical row; local checks are advisory and the owner repeats full preflight. Close may abandon active assignments when the owner permits it; confirmation names that loss. Unretrieved results can still cause an owner refusal.
6. **File-client boundary choices.** Publication uses a 0600 temporary sibling plus an atomic non-overwriting hard link. Results bind both request id and submitted operation, use no-follow/nonblocking open, require a regular file and read at most 8 KiB plus one byte. Directory trust is checked on every access, not merely at client construction. Invalid evidence is a diagnostic, never an absent result. UUID v4 comes from kernel randomness and UTC timestamps use the standard clock with strict checked parsing; no dependencies were added.

**Files are authoritative.** Use owner-created user-owned 0700, non-symlink directories; atomic 0600 request files bounded to 8 KiB with UUID ids and 30-second absolute expiry. Do not create the owner directories. Reuse serde, existing libc and std facilities where possible; any needed UUID/time utility earns its dependency through this consumer. Request publication must not replace another request. Result parsing is bounded and validates version, request id and operation before accepting an outcome; unknown fields are tolerated.
7. **No timeout verdict.** Derive result, started, not_executed, pending in that order from files. A claim without a result means started/outcome unknown, never a retry. Later result files can refine that display. Malformed or unreadable evidence is a diagnostic, not not_executed. UI shutdown does not retract a published request. Track outstanding/unknown actions by exact target to prevent accidental duplicate submissions; keep outcome visible until dismissed, separate from source/focus diagnostics.
8. **No optimistic removal.** Collection reconciles effects normally. A result may request refresh but does not remove rows or invent relaunched state. The owner token is optional wake evidence, not needed for correctness; do not expand the metadata bus.
9. **Acceptance and runtime readiness are distinct.** Before managed-action implementation is enabled, obtain and record owner acceptance of the current contract/fixture and implementation. At runtime missing/untrusted owner directories refuse safely; an old owner process is not assumed to have loaded newly landed code merely because its pane UUID is unchanged.

10. **One managed-action worker, separate outcomes.** Publication and file polling share a persistent off-thread worker with exact owner/label/run duplicate suppression. Pending, Started and Unknown retain their target until a known result resolves it; a notice dismissal cannot unlock re-submission. Persistent footer outcomes are separate from source/focus diagnostics and `c` dismisses them. Rejected: a thread per request or settling Unknown merely because a result file exists.
11. **Restart needs both idle signals.** Owner-advertised idle is required, and the derived activity must also be idle. Derived Unknown is not permission to restart. The owner repeats authoritative eligibility checks.

## Risks / Trade-offs

- [Existing owner processes retain old code] → owner acceptance permits implementation, not capability inference. Processes must reload to create/watch their control directories; missing metadata or directories means unavailable/unknown, never unmanaged.
- [Containment changes during confirmation] → freeze identities, revalidate, refresh before direct close; refuse drift. Atomic conditional mux close is not available in the documented CLI.
- [Close abandons useful work] → name pane process/assignment and outstanding work in confirmation; owner preflight is never bypassed.
- [Radar quits after publication] → say requests remain owner-executable; no cancellation or retry claim.
- [Claims and result retention differ] → use the exact file precedence; never infer no effect from missing results or a local deadline.
