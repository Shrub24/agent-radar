# Design

## Decisions

- **Dedicated tmux server.** The adapter targets a named socket (`tmux -L <name>`), never the user's default server. Selection is explicit configuration; the daemon refuses to start with an unknown backend.
- **Handles.** Locations use tmux's stable ids (`$session`, `@window`, `%pane`), qualified by backend and socket name. Labels and indexes are never identity.
- **Mapping.** session ≈ workspace, window ≈ tab, pane ≈ pane. Anything tmux cannot express is refused by an undeclared capability, never emulated.
- **Launch.** Spawn has already created the pane, so tmux replaces its shell with `respawn-pane -k -t <pane> -c <cwd> -e K=V … <executable> <argv…>`. tmux executes multiple command arguments directly, without `sh -c`; the overlay adds/replaces variables while preserving the pane's inherited session environment. Absolute cwd and token rules from `child-launch-binding` still apply.
- **Remain-on-exit.** Set the exact pane's `remain-on-exit` option before `respawn-pane`; if the option cannot be set, refuse before dispatching the child. This works for an immediately exiting child and retains the status in the pane.
- **Launch transport exposure.** tmux's `-e` values (including `PI_RADAR_SPAWN_TOKEN`) are transient arguments to the tmux client and are readable from `/proc/<pid>/cmdline` on this host's procfs mount (`hidepid` is unset; cmdline mode is 0444). They are not included in daemon diagnostics, operation results or test logs. The socket and runtime directories are owner-only, so a different UID cannot connect to the named tmux server or daemon; same-UID processes are already inside the daemon's local trust boundary. Avoiding transient argv exposure would require a private launch-file/exec helper or tmux control-mode transport and is deferred unless the trust boundary changes.
- **Exit observation.** Read `#{pane_dead}`, `#{pane_dead_status}`, `#{pane_dead_signal}` and `#{pane_dead_time}` in one bounded `list-panes` query for each topology page. A dead pane with a valid code or signal records the first observation on its spawn edge, with Radar's observation time; retries preserve that fact. `spawn.get` and `spawn.list` expose `{state:"unknown"}` until a v2 edge has a confirmed exit, then `{state:"exited", code|signal, observed_at}`. `pane-died` hooks are unnecessary.
- **Honest absence.** A retained dead pane yields a typed exit. A pane gone with no recorded exit stays unresolved; a missing server stays unknown.
- **Dead-pane close.** Exit observation does not authorize `child.close`. Managed close still requires fresh inventory, unchanged containment and a current foreground-process birth-identity match. A dead pane has no live foreground identity, so `child.close` refuses before durable close admission or dispatch. Do not substitute the recorded exit for process-identity evidence; any future dead-pane cleanup needs its own proof that the exact pane remains dead immediately before dispatch.
- **No resume/stop.** Exit observation is physical fact only; it never completes an assignment or alters execution publications.
- **Herdr parity.** Herdr keeps typed-line launch and has no exit-observation capability; current v2 edges therefore read `{state:"unknown"}`. Legacy v1 edges omit the field.

- **Selector channel.** The daemon backend is chosen by `RADAR_CONTROL_BACKEND` (`herdr` default, `tmux`) plus `RADAR_TMUX_SERVER`, the daemon's existing environment channel beside `RADAR_CONTROL_SOCKET`/`RADAR_CONTROL_STATE`. It is resolved before the socket or state directory exist, so a refused backend leaves nothing behind. Alternative: a `[daemon]` section in the dashboard `config.toml`; rejected because it would couple daemon startup to unrelated client config errors. Revisit if the selector must ride generated Nix settings.
- **Adapter decisions (task 1.2).** Handles are `tmux:<server>:<id>` over `$N`/`@N`/`%N`, parsed strictly; server names are `[A-Za-z0-9._-]` and `default` is refused, so the user's default server is unreachable by construction. Every command is `tmux -L <server>` with `TMUX` stripped. Workspace focus uses `switch-client`, so it is `unknown` without an attached client; workspace creation with `focus: true` is refused rather than created-then-switched; pane focus is two dispatches and reports `unknown` if the second fails. Output has no content revision. Foreground evidence is `#{pane_pid}` plus `#{pane_current_command}`, which name the same process only while it holds the terminal, so the guarded close gate fails closed for shell-hosted agents; direct-argv children (task 2.1) make `pane_pid` the child itself. Tests use checked-in stand-in scripts, not runtime-written executables (ETXTBSY flakes).

## Risks and limits

- tmux 3.7 option and format names must be verified against the installed binary in the smoke, not assumed.
- If a same-UID client externally respawns a daemon-managed pane before Radar first observes its death, tmux can replace the retained exit status. Verified on tmux 3.7c with an isolated named server: `pane_dead_status` changed from 23 to 17 after `respawn-pane -k`. The current adapter has no pane-process-generation token, so a later status is tmux's pane-command observation, not independently verified identity of the bound agent; external respawn is within the existing same-UID trust boundary.
- A killed tmux server loses all panes; recovery is out of scope.

## Resolved question

A dead-pane exit does not authorize `child.close`. The operation remains fail-closed on fresh foreground process birth identity; dead panes without a live foreground identity refuse before durable admission and dispatch. A future cleanup path needs separate exact-pane-dead proof.
