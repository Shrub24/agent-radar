## Correctness review follow-up

- Actor-recorded refusals consume action numbers just like applied actions; transport/mailbox Busy does not. The real-client editor test now follows refusal with two valid navigation actions without reconnecting.
- Pending-action accounting follows ownership of the queued/in-flight action, including cancellation while awaiting a reply; an essential-task failure cannot leave the replacement attachment permanently pending. A focused action-pump cancellation regression covers this.
- Content, action and demand requests share one allocator. A focused materialisation test holds demand outstanding through three missing-payload fetches and checks correlation remains intact.
- Both ends observe any essential task ending through one `JoinSet` owner, then await sibling cancellation. The reader-only policy left failed materialisers and server writers half-alive. Removed the client's duplicate reader-closure channel; task supervision owns termination.
- Established UI reads wait indefinitely for a first byte; only started frames have a completion deadline. Ordinary connections retain their idle policy. The framing and essential-task tests cover these boundaries without a two-minute sleep.
- Maintained design already requires these behaviours; these are implementation corrections, not a new architecture. Routine gate passed: fmt, strict Clippy, all Rust targets including the pending-count correction (544 library tests, 171 control-plane tests, all other suites), 111 SDK tests, all three active changes validated strictly, whitespace checks and rationale lint.
